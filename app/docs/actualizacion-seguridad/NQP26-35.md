## Implementación para revisión

MICRO_RECEIPT_RECTIFY mantiene ADMIN, identidad documental, fecha original,
request original, gasto y conjunto de microinsumos. Requiere versión documental,
revisión global, fecha efectiva, motivo y referencia. Conserva renglones originales
y archiva cada versión; PURCHASE_ADJUSTMENT registra exclusivamente el delta
firmado de gramos/céntimos. Un cambio de precio tiene delta físico cero. No se
utiliza ISSUE ni RETURN para corregir compras. La transacción incluye cabecera,
renglones, libro, gasto, corrections/correctionFields y auditoría; replay verifica
actor, comando y carga. La UI fija la solicitud después del intento para recuperar
una respuesta perdida mediante el mismo request_id.

La diferencia monetaria completa modifica el valor remanente conforme a la
autorización humana anterior. Se conserva la aritmética racional y el carry de
ISSUE; ningún consumo, retorno histórico, preparación, cierre o venta se recostea.
Saldo libre considera asignaciones pendientes. Valor negativo, cantidad negativa
o valor no cero sin stock rechazan todo el comando. Si el saldo y valor admiten
la diferencia, un cierre previo no exige recuperar material ya consumido.
Compras documentales anteriores al corte y logística conservan sus flujos.

Migración0012 aditiva sin tablas nuevas ni modificaciones0000–0011. Refuerza
ecuación física, identidad/versiones, conciliación de gasto y cadena de eventos.
Importación coteja auditoría original, todos los renglones/versiones, metadatos
económicos, snapshots, deltas y cobertura de eventos. Esto detecta inconsistencias;
no proporciona autenticidad criptográfica frente a quien reescriba toda la base.
Upgrade requiere respaldo y preparación administrativa externa; no se ejecuta
migración ni carga de datos al arrancar.
