## Contrato

- ROSADO: Potripregnant. VERDE_AMARILLO: Hi-Performance y Nutrelin Adulto, una sola familia compartida.
- microFormulas y microFormulaLines son snapshots nuevos por cada guardado. Incluyen familia, versión monotónica, autor/fecha, observación, dosis en gramos enteros y nombre/ID operativo histórico.
- microFormulaHeads contiene un único puntero activo por familia. La versión de cabecera es el token CAS; no confundirla con el número de receta. Cero activas inicialmente es válido.
- MICRO_FORMULA_SAVE: family, expected_version (0 al comenzar), lines [{micro_ingredient_id, dose_kg decimal string hasta3 decimales}], notes opcional. Crea borrador inmutable, incluso vacío; no altera la activa. Editar significa crear otro snapshot.
- MICRO_FORMULA_ACTIVATE: family, expected_version, formula_id. Solo borrador posterior a la activa, no vacío y con insumos activos. Publicar conserva identidad/dosis y registra autor/fecha. Una publicada nunca se edita, elimina ni reactiva.
- No se exige artificialmente17 renglones para ampliar el catálogo: una receta no vacía con dosis expresas se considera completa bajo responsabilidad ADMIN. Faltan ingredientes no registrados: conservar borrador, no inventarlos.
- Se enlaza al ID técnico permanente de microIngredients mediante FK, no por nombre. El ID operativo14 sigue reservado por el catálogo. No hay seed ni importación automática.
- request_id usa replay canónico existente por actor y payload; otra carga con mismo ID rechaza. CAS global de settings evita escrituras perdidas entre procesos; CAS por familia rechaza decisiones obsoletas.
- Migración0004 aditiva: tres tablas, FK/UNIQUE/CHECK, triggers de inmutabilidad/publicación/identidad. JSON y columnas SQL concordantes. Una transacción persiste cabecera, renglones, puntero y auditoría.
- microFormulaRequirement es cálculo puro: recibe líneas y núcleos hasta2 decimales, devuelve centésimas de gramo enteras exactas. No redondea gramos ni genera movimientos. No se conecta a producción en este alcance.

## Interfaz y límites

Vista añadida dentro de Microinsumos sin mover navegación ni fórmulas MACRO. Muestra únicamente la activa de cada familia; historial y borradores plegados. ADMIN crea y activa; OPERATOR/VIEWER consultan. Nombres de líneas históricos sobreviven al renombrado/desactivación del catálogo. Activar una receta con insumos desactivados rechaza; conservar una activa histórica al desactivar catálogo no altera su contenido.

Sin sustituciones NQP26-25, consumos NQP26-28, reservas, cambios de stock, compras, gastos ni producciones/costos históricos. Preparación futura debe referenciar formula_id inmutable, sin sustituir retroactivamente referencias. No se usan bases reales, despliegue ni merge.
